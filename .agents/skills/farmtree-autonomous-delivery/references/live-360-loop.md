# FARMTREE LIVE 360 LOOP

Use only for a requested comprehensive FarmTree live quality programme. Read
the current brief, AGENTS, current sprint and docs/audit/live-360/state.json.
Git remains code authority; production is the acceptance environment. Approved
manual production content is not code drift to overwrite: reconcile its ownership
and approval before any write. Never modify production alone to close a finding.

## Establish and preserve scope

Independently verify source/local/remote/artifact SHAs, dirty files, runtime
versions, active theme/plugins, public routing, indexing, Coming Soon, reserved
locales and Bot state at each major phase. Historical documents are evidence
of past state, not instructions to restore obsolete private-review settings.
Store no credentials, private-review tokens, user records or raw sensitive logs.

Use current primary standards references; distinguish framework alignment from
certification and clause-by-clause compliance. A catalogue abstract does not
substitute for access to a licensed normative standard. Never invent user-study,
screen-reader, field performance, organisational or legal approval evidence.

## Assessment and remediation

1. Define a fixed measurable acceptance checklist per requested discipline before
   scoring. Record tests, evidence type, applicability and the rationale for N/A.
2. Obtain independent discipline assessments before consolidation when requested.
   Separate role perspectives explicitly; AI reviews are not human panel sign-off.
3. Store baseline, route inventory, evidence index, risk register and progress in
   docs/audit/live-360/. Keep bulky generated captures in ignored qa/live-360/;
   record digests and reproducible commands so missing evidence is detectable.
4. Prioritise P0 security/data/stability; then P1 correctness/accessibility,
   performance/search and UX; then P2 maintainability/copy; finally P3 polish.
5. For each issue record actual production evidence, reproduction, root cause,
   minimal source change, regression, release SHA, backup and production retest.
   A local PASS alone cannot close a production finding.
6. Validate -> focused commit -> authorised feature-branch push -> audited exact
   artifact -> verified off-webroot backup -> scoped deployment -> production QA.
   Read current explicit authority before mutations. Use stronger gates for
   content/database/security/rewrite changes. Verify ownership, reviewed dry-run
   digest and unaffected production state. Restore the verified backup on a
   critical deployment regression, then repair source and revalidate.
7. Do not weaken tests to remove a failure. For a harness defect, first demonstrate
   actual behaviour using an independent observable outcome and keep equivalent
   regression coverage. A timeout is not itself proof of failed interaction.
8. Re-audit the affected discipline and regressions after each release. Do not
   redesign approved visuals or change scientific/legal claims without evidence.

## Diagnostics and stopping

Escalate from source/test inspection to DOM/HTTP/logs/runtime values, minimal
local reproductions, hook/network tracing, environment comparison and independent
second review. Production diagnostics must remain within current authority and
be rollback-protected where they can write. Do not delete uncertain files/data,
change unrelated services, disable safeguards or run intrusive load/security tests.

Continue safe controllable work while external evidence is pending. Stop a risky
path for missing authority, credentials, unavailable infrastructure, third-party
outage, a real business/legal choice or ambiguous manual-data ownership. Report
the precise needed decision/action; do not disguise a normal bug as a blocker.

## Scores and handoff

Use the user-approved weights without changing thresholds mid-programme.
Score from fixed criterion results: PASS, FAIL, UNKNOWN, MANUAL-VERIFY or N/A.
Unknown/manual criteria earn no verified credit, even if they are external.
Report numerator, denominator, coverage and missing evidence; 100/100 requires
all applicable criteria verified, no P0/P1 and no known controllable blockers.
Subjective critique remains an AI assessment unless actual human research exists.

Produce the brief's final matrices, architecture/inventory/changelog, evidence
index and machine-readable scorecard. Label VERIFIED, ALIGNED, PARTIALLY VERIFIED,
MANUAL/ORGANISATIONAL EVIDENCE REQUIRED or NOT APPLICABLE. Never label an incomplete
programme complete or ISO certified. Keep state.json honest so another session
can resume at the next unresolved issue without repeating completed releases.
