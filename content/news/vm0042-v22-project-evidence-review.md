A methodology version is a useful reference, but it is not a complete specification of a carbon project's evidence requirements. Corrections, linked tools and the version applicable to the project also matter. A review that checks only whether a document says “VM0042 v2.2” can therefore miss a material change in the work expected from the project team.

## Read the active methodology with its corrections

Verra lists VM0042 v2.2 as active from 21 October 2025. It addresses greenhouse-gas emission reductions and soil organic carbon removals from improved agricultural land management. The official page also states that v2.1 remains active. It is inaccurate to describe v2.2 as the only version available or to infer that the methodology makes every agroforestry project eligible.

On 11 June 2026, Verra published corrections and clarifications for v2.2 that apply from their issuance date. Among the changes, the document clarifies baseline descriptions for grouped projects and evidence for the additionality barrier analysis. It also states that the methodology-level baseline justification in Appendix 3 does not need to be replicated for each project. These points do not eliminate the need to describe the actual pre-project practices relevant to a project.

Those statements come from Verra's methodology page and corrections document. The review process proposed below is FarmTree editorial analysis, not a substitute for the methodology, linked tools or a validation/verification body's assessment.

## Build a change register that reaches the working files

Begin with the source documents actually used by the team. Record the methodology version, correction date, applicable linked tools and the assessment stage. Keep that record next to the project evidence, not only in a presentation prepared for investors. The person maintaining a sampling file needs access to the same interpretation as the person writing the project description.

For each relevant correction, identify the affected working artefact. That might be a baseline narrative, a data-collection form, an eligibility-area description, an additionality evidence table or a calculation workbook. Record whether it has been reviewed, whether an amendment is needed and who accepted the conclusion. “No change required” can be a sound result, but it should have a reason rather than mean that nobody looked.

A useful internal check is to select one changed provision and follow it from the official document into the team's working instructions. If the only record of the change is a link in an email, implementation has not yet been demonstrated. Conversely, do not rewrite unaffected files simply to create the appearance of a comprehensive response.

## Describe the baseline at the level where practices differ

For grouped projects, a single high-level account can conceal differences between participating farms. As a practical review technique, separate the description of historical practice from the description of the proposed change. Ask whether each part of the evidence file makes that distinction consistently.

Suppose two participating farms have different crop rotations or residue-management arrangements. A shared project objective does not make their historical records interchangeable. A team should be able to explain which differences are relevant to its baseline description and eligibility assessment, and which are not. That explanation belongs in the evidence trail rather than in an undocumented spreadsheet adjustment.

Avoid confusing a simpler methodology-level justification with permission to omit project facts. The operational opportunity is to direct effort towards the evidence the method actually requires, rather than reproduce an unnecessary generic analysis. Have the responsible technical reviewer confirm that the reduced workload has not removed information needed elsewhere in the assessment.

## Treat additionality evidence as an argument that can be checked

An evidence table is more useful when it records what a source establishes, not simply its title. For a barrier-related claim, note the specific assertion, geographical relevance, time period and limitations of the supporting material. Separate direct evidence from a contextual source that only describes the wider sector.

Where evidence is missing, write down the gap. Do not promote an internal expectation into an independent finding because the project needs a completed document. If a source concerns a different region, practice or period, the reviewer should see that limitation before deciding how much weight to place on it.

This approach also makes updates more efficient. When a new publication arrives, the team can assess which argument it affects instead of rebuilding the entire file. Keep the earlier evidence and the reason for replacement so that someone reviewing an older decision can reconstruct what was known at the time.

## Keep monitoring changes separate from editorial changes

A correction to a method can have consequences beyond the project description. Before issuing revised instructions, check whether the sampling team, laboratory, data manager or modelling team needs to act. Changes that affect measurement or calculation should have a controlled implementation record; a revised heading or explanatory paragraph should not be presented as if it altered the underlying evidence.

For model-based work, preserve the relationship between source data, preprocessing, parameter choices and outputs. If a calculation is rerun, retain the previous result and explain whether the difference comes from new observations, corrected processing or a revised assumption. Those are different reasons for change and can require different responses from reviewers.

Agroforestry scenario comparison can help structure questions about management and projected outcomes. The [FarmTree Platform](/platform/) should not be presented as issuing credits or replacing validation. Our companion discussion of [CRCF model recognition](/crcf-model-recognition-evidence/) considers a different framework and should not be treated as an interchangeable compliance route.

## A proportionate review before the next assessment

The immediate takeaway is to commission a documented applicability review of the correction set against the project's current evidence file. Resolve material changes with the responsible specialists, assign outstanding work and retain the review record. That is more useful than changing the version label on the cover page while leaving the operating procedures untouched.
