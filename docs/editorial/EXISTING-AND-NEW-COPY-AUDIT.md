## Copy, relevance and route checks

- All eight were read in full. They have different titles, decks and central
  decisions. Their shared evidence-governance vocabulary is thematically coherent
  but noticeable; the final page should not present several governance-heavy
  articles as if they cover unrelated topics.
- An exact-text comparison found no repeated body paragraph longer than 120
  characters between these eight and no verbatim reuse of an old article's
  section body. This is a bounded exact-overlap check, not a plagiarism scan.
- New CRCF, EUDR, VM0042 and restoration pieces overlap old topics but add
  operational angles: project evidence design, integration handovers, correction
  review and condition measurement. Preserve both records and avoid duplicate
  card excerpts or claiming twelve wholly unrelated topic areas.
- Conclusions use similar decision-pack language. They remain differentiated by
  the specific decision and recommended artefact, but typography/layout and
  topical sequencing should prevent the hub from feeling like one repeated card.
- No fake named author, quote, field result, performance statistic or claim of
  FarmTree certification was identified in these eight. Recommendations are
  labelled as interpretation rather than represented as source quotations.
- Source availability is not a licence to reproduce full reports, tables or
  figures. These drafts use brief factual summaries and original interpretation;
  no source illustration was copied in this audit.
- `/proof-stories/farm-value-projection/` is the correct repository route:
  `farmtree-content.php:91` registers `proof-stories`, and `data/proof-stories.json`
  retains `farm-value-projection`. The legacy `farm-value-modelling` redirect also
  points there. Visible wording remains **Farm Valuation**. This source check is
  not a fresh HTTP result; the main route suite must check the actual runtime.
- New cross-article root slugs require their corresponding new posts before
  publication. They must not be claimed as currently live destinations. Local
  rendered canonical, H1, Article metadata, accessibility and link tests remain
  the main implementation's responsibility.
